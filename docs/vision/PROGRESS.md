# Фактический статус реализации

Ветка: `codex/browser-vision-stage1`.
База: `main`, commit `80a6fdfebb976c88b1eccb2311dde7dfaa0268d0`.

## Готово к первому запуску на устройстве

- Основной интерфейс: локальный видеофайл или камера → детектор изменений → OCR
  и шаблоны карт в браузере → поля, карты и JSON. Ключ API и серверная сессия не нужны.
- Профиль Open Poker 1206×2622, редактируемые пять областей, сохранение/импорт/экспорт
  с проверкой структуры. Пользователь явно подтверждает совмещение перед запуском.
- OCR Tesseract.js 7.0.0 и закреплённая английская модель; Worker/WASM/модель выдаются
  тем же сайтом. Карточный модуль принимает отдельный файл с девятью шаблонами из записи.
  Без загрузки шаблонов текстовый OCR работает, карты остаются неизвестными.
- Детектор в отдельном Worker, проверка 5 Гц, 400 мс покоя, локальный safety poll 2 с.
  Один активный OCR и один последний ожидающий кадр, минимум 1 с между запусками.
- Инвалидация при изменении, защита от старой сессии/калибровки/ревизии и ответов
  старше 5 с. Пауза/перемотка/конец/ошибка/скрытая вкладка закрывают наблюдение.
- Версионированный локальный контракт, последние 100 наблюдений в экспорте JSON.
  Все результаты частичные: `decision_ready=false`, неизвестные поля `null`.
- Серверная консоль сохранена в `/server.html`: отдельный FastAPI, mock/OpenAI,
  strict schema, глобальная очередь, лимиты/backoff и серверный reducer/replay.
- Документация запуска и границ, исходные пошаговые промпты, команды проверок и CI.

## Проверено автоматически

`npm run verify` прошёл целиком после интеграции локального режима:

- **64 Vitest** с локальным набором изображений, включая прежние 35 и 29 новых.
- Без приватного набора: **62 passed, 2 skipped**. Только два теста реальной записи
  требуют отдельного архива; публичный CI их не выполняет. `npm run test:recording`
  требует наличие набора и не считает отсутствие изображений успешной проверкой.
- **139 pytest**, включая все 87 исходных тестов моста.
- Strict TypeScript, Prettier, Ruff, архитектурные границы.
- Production Vite build: два HTML-входа, отдельные Worker детектора и карт.
- ASGI smoke выдачи обоих интерфейсов, JS/CSS, OCR Worker, всех трёх вариантов
  WASM и английской модели. Старый endpoint исполнения отсутствует в новом app.

Контроллер проверен с настоящим чистым детектором и подменёнными браузерными API:
новый кадр обязателен даже при ручном запросе, пиксели/профиль не меняются под
ожидающим OCR, старый ответ не применяется после перемотки, паузы, конца видео,
ошибки или остановки во время запуска. Gate проверяет замену ожидающего кадра,
лимит частоты, освобождение просроченной задачи и подтверждение двумя захватами.

## Что удалось прочитать на предоставленной записи

Источник: `ScreenRecording_09-11-2026 19-34-33_1.MOV`, 1206×2622, 52,55 с,
одна раздача Open Poker #4812. Десять контрольных кадров: 2, 18, 22, 26, 30, 34,
38, 42, 46, 50 секунд. Реальная npm-модель OCR запускается в Node/WASM на кропах;
подготовка пикселей и парсер общие с браузерной реализацией.

- Номер раздачи, этап и LIVE/REPLAY: **10 из 10** контрольных кадров.
- Текущий банк: **8 из 8** LIVE-кадров, значения 30, 116, 174, 232, 399, 733,
  1094, 1288. Оба Replay не выдают текущий банк, AWARDED не считается банком.
- Борд на 42 с: `6c Qd Tc 2h Kh`; на 22 с: `6c Qd Tc`.
- Перекрытие на тёрне не заполняется догадкой; несовпадение числа найденных карт
  с этапом оставляет позиции неизвестными. Пустое изображение не даёт карты.

Карточные шаблоны берутся только из Replay-кадра 50 с. Live-кадры проверяют другой
момент той же раздачи, а не независимый набор. Есть 9 лицевых сторон из 52 и ни
одной пики. Эти результаты НЕ оценивают качество на других раздачах, интерфейсах,
физических картах или неизвестных шаблонах; возможны ошибочные совпадения.
Подробности происхождения и воспроизведения: `tests/vision-fixtures/README.md`.
Изображения и шаблоны хранятся в отдельном архиве и исключены из Git.
После отклонения их публикации автоматической проверкой разрешений в GitHub
передаётся только код и документация. Шаблоны загружаются пользователем локально.

Прежний синтетический замер чистого детектора, Node 24.19.0, 640×360, 10 областей,
120 измерений после прогрева: p50 10,93 мс, p95 13,05 мс, максимум 18,22 мс.
Он сохранён в `benchmark.json` и не включает decode/Canvas/Worker/OCR. Производительность
полного цикла на устройстве пользователя по этому замеру не определяется.

## Ещё не подтверждено

- Облачный браузер отклонил тестовый адрес своей политикой доступа
  (`ERR_BLOCKED_BY_CLIENT`, затем explicit URL policy rejection). Визуальная
  приёмка и настоящий browser E2E здесь не выполнялись.
- Физическая вебкамера пользователя не проверена. Частота и задержка полного
  браузерного конвейера, перспектива, дрожание, освещение и шрифты ещё не оценены.
- Live OpenAI API не вызывался. Локальный режим не требует такого вызова.
- Docker-конфигурация учитывает новые статические модели, образ здесь не собирался.
- Профиль привязан к геометрии и стилю интерфейса. Изменение прокрутки при тех же
  размерах автоматически не обнаруживает ошибочную калибровку.
- Стеки, места, карты героя, полный борд всей колоды и история действий остаются
  следующими этапами. Частичный JSON не передаётся сервису решений или роботам.
- Серверная очередь в памяти одного процесса, локальная — в памяти вкладки;
  долговременный журнал появляется только при экспорте.

Draft PR остаётся для проверки и запуска на устройстве, без автоматического
слияния. Шаги 11–12 исходного плана требуют ручной приёмки по `IMPLEMENTATION.md`.
