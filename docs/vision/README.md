# Table Vision: первый этап

Результат этой ветки — отдельное приложение, которое открывает вебкамеру или
локальное видео, обнаруживает значимые изменения в браузере и отправляет выбранные
снимки серверу. Сервер вызывает OpenAI, проверяет JSON и показывает наблюдаемое
состояние стола. Вызовов сервиса решений и роботов в этом приложении нет.

## Запуск за пять шагов

Нужны Node.js 22.12+ и Python 3.11+ с `uv`. Команды выполняются из корня репозитория.

1. Установить зависимости: `npm ci` и `uv sync --frozen --extra dev`.
2. Скопировать `.env.example` в `.env`. Начать с `VISION_MODE=mock`.
3. Собрать интерфейс: `npm run build`.
4. Запустить `uv run uvicorn app.vision.api:app --host 127.0.0.1 --port 8001 --workers 1`.
5. Открыть `http://localhost:8001` в своём браузере. Ввести `RECEIVER_TOKEN` из `.env`.

Синтетическая сцена открывается без разрешения камеры. Нажать «Начать наблюдение»,
затем «Изменить сцену». В mock-режиме JSON намеренно содержит неизвестные значения:
это проверка доставки и детектора, а не имитация успешного распознавания карт.

Для камеры нажать «Включить камеру», разрешить доступ и выбрать устройство.
Для её полного отключения повторно нажать кнопку камеры. «Стоп» останавливает
наблюдение и отправку снимков, оставляя превью для калибровки. При скрытии вкладки
наблюдение останавливается. Переключение на демо выключает видеотреки.

Выбрать каждую область и обвести её на видео. `seat_0`…`seat_5` — фиксированные
физические места, а не позиции относительно дилера. Настроить место героя, единицы
и число десятичных знаков. Для USD с двумя знаками `12.34` хранится как `1234`.
Маски исключают таймеры из сравнения. Профиль можно сохранить, экспортировать и
импортировать; после смены камеры его нужно проверить на новом кадре.

## Настоящее распознавание

В `.env` на сервере установить:

```dotenv
VISION_MODE=live
OPENAI_API_KEY=your-server-api-key
OPENAI_VISION_MODEL=gpt-4.1-mini
RECEIVER_TOKEN=your-private-random-token-at-least-24-characters
VISION_TIMEOUT_SECONDS=15
```

Перезапустить сервер. В интерфейсе появится LIVE и выбранная модель. Поле токена
в интерфейсе предназначено для `RECEIVER_TOKEN`, ключ OpenAI туда не вводится.
Ключ OpenAI не передаётся в браузер и не входит в записи. Реальные API-вызовы
платные. Модель настраивается переменной окружения; ответ проверяется независимо
от её уверенности. Отказ, таймаут и некорректный JSON видны как ошибки, без перехода
на mock.

По умолчанию передаётся весь выбранный видеокадр, включая области вне контуров.
Контуры управляют отбором и помогают модели сопоставить места. Перед началом
направить камеру на стол так, чтобы в кадр не попадали ненужные окна. Маска
детектора не является скрытием части изображения при отправке.

## Проверка кода и диагностика

- `npm run verify` — TypeScript, форматирование/lint, архитектура, Vitest,
  весь существующий pytest, сборка и проверка статических файлов через ASGI.
- `npm run verify:step -- 04` — автоматические проверки выбранного этапа 01…12.
  Соответствие этапов описано в `IMPLEMENTATION.md`.
- `npm run benchmark` — время чистого детектора на синтетических кадрах в Node.
  Это не замер камеры, Worker или точности распознавания.
- «Скачать запись» — исходные отправленные изображения, ответы, события и профиль.
  После остановки последняя доступная запись остаётся в памяти страницы.
- `uv run python -m app.vision.replay recordings/example.json` — воспроизведение
  сборки состояния без сети и без затрат API.

Запись ограничена 16 МБ / 100 событиями. `dropped_records` показывает усечение,
`queue_at_export` — незавершённую работу. Для воспроизведения детектора нужен
исходный видеофайл: одних отправленных снимков недостаточно. Серверные сессии
хранятся в памяти и не восстанавливаются после перезапуска. Сохранённый файл записи
остаётся единственным долговременным диагностическим артефактом этой версии.

## Развёртывание

`docker compose -f docker-compose.vision.yml up --build` поднимает только первый
этап на `127.0.0.1:8001`. Для другого устройства нужен HTTPS через ваш reverse
proxy: браузер не даёт камеру обычному HTTP-сайту на внешнем адресе. Один процесс
`--workers 1` обязателен: очередь и лимиты находятся в памяти этого процесса.
Горизонтальное масштабирование потребует общего координатора очереди.

Существующий мост по-прежнему запускается через `app.main:app` на порту 8000.
Не отправлять частичный JSON камеры на его `/v1/events`: эта точка уже запускает
принятие решений. Следующий этап получит отдельный адаптер и критерии готовности.

Текущее состояние проверок и ограничения: [PROGRESS.md](PROGRESS.md).
