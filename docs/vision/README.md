# Table Vision: первый этап

Результат — сайт, который открывает вебкамеру или локальное видео, обнаруживает
изменения и распознаёт выбранные кадры прямо в браузере. Ключ API не нужен,
изображения не загружаются на сервер. На экране и в JSON доступны номер раздачи,
этап, метка LIVE/REPLAY, видимый банк и поддерживаемые общие карты. Нечитаемое
значение остаётся `null`; это частичное наблюдение, а не полное состояние для игры.

## Быстрый запуск локального режима

### GitHub Pages: открытие по ссылке

Версия Pages содержит только локальное распознавание. Node.js и Python на устройстве
посетителя не нужны: браузер загружает страницу, Worker и OCR-модель, затем обрабатывает
камеру или выбранный видеофайл. Шаблоны карт по-прежнему выбираются локально из архива.

Публикация подготовлена в `.github/workflows/pages.yml` и запускается после push
в `codex/browser-vision-stage1`. Слияние PR в `main` для этого не требуется.
Владелец репозитория один раз выбирает **Settings → Pages → Source → GitHub Actions**.
Если запуск уже завершился ошибкой из-за выключенного Pages, после настройки нужно
повторить его через **Re-run all jobs**. Пока workflow отсутствует в `main`, кнопка
ручного **Run workflow** может быть недоступна. Для приватного репозитория требуется
тариф GitHub с поддержкой Pages; делать исходный код публичным не требуется.

При явной ошибке ограничения ветки в окружении `github-pages` разрешить
`codex/browser-vision-stage1` в **Deployment branches and tags** этого окружения.
Workflow загружает только `dist/pages`: серверный интерфейс, исходники и приватные
изображения в артефакт не входят. Публикация пользуется стандартным токеном Actions,
дополнительный персональный токен не нужен.

Проверка этой версии разработчиком:

```bash
npm run build:pages
npm run check:pages
```

Сборка использует относительные пути и работает в подпапке репозитория. Проверка
контролирует HTML, JS/CSS, оба Worker, OCR-модель/WASM и отсутствие приватных данных.
Камере нужен HTTPS и разрешение пользователя. Поддержка конкретного MOV/HEVC
по-прежнему зависит от браузера. Успешная сборка не заменяет проверку на устройстве.

### Запуск на своём компьютере

Нужен Node.js 22.12+. Из корня репозитория:

```bash
npm ci
npm run dev
```

Открыть `http://localhost:4173`. Python, `.env`, токен сервера и MCP для этого режима
не нужны. При установке скачиваются npm-зависимости; при открытии страницы Worker,
WASM и английская модель загружаются с того же сайта. Это не означает, что сайт
заранее доступен офлайн: service worker для автономной установки пока не добавлен.

1. Нажать «Открыть видео» и выбрать исходную запись Open Poker либо включить камеру.
2. На приостановленном видео проверить пять контуров. Выбрать поле и обвести его
   заново, если контур не совпадает. «Число банка» должно охватывать только цифры,
   «Банк — панель POT» — всю подпись и сумму. Профиль записи рассчитан на 1206×2622.
3. Для карт распаковать приложенный `table-vision-recording-fixtures.zip`, нажать
   «Загрузить шаблоны карт» и выбрать `tests/vision-fixtures/templates.json` из архива.
   Это локальная загрузка в память страницы. Без шаблонов OCR работает, карты
   остаются неизвестными. После перезагрузки страницы шаблоны нужно выбрать снова.
4. Отметить «Области совпадают с полями на моём видео» и начать наблюдение.
5. Смотреть поля, карты, JSON, счётчик распознаваний и время обработки.
6. Скачать наблюдения JSON. В памяти остаются последние 100 результатов, без
   исходных видеокадров. Новая сессия создаёт новый журнал; прежний нужно скачать.

Кнопка камеры повторным нажатием освобождает видеотреки. «Стоп» останавливает
распознавание, оставляя превью. Пауза, перемотка, конец записи, ошибка видеовхода
и скрытие вкладки закрывают сессию наблюдения. Для продолжения снова нажать
«Начать наблюдение». При смене размеров кадра требуется новая калибровка.
Поддержка исходного HEVC/MOV зависит от браузера; при ошибке использовать MP4 H.264.

## Как экономим распознавания

Детектор сравнивает уменьшенные RGB-кадры в Worker 5 раз в секунду, только внутри
областей профиля. Ожидает 400 мс покоя; непрерывное движение не блокирует диагностику
бесконечно. OCR запускается не чаще раза в секунду. Одновременно обрабатывается
один кадр и хранится только последний ожидающий. Неподвижный стол перепроверяется
через 2 секунды. Повтор замершего видеобуфера не считается новым захватом.

Изменение сразу убирает старые поля с экрана. Ответы старой сессии, ревизии или
старше 5 секунд не применяются. Два совпавших стабильных чтения получают признак
`repeated`; общее состояние всё равно `partial` и `decision_ready=false`.

## Границы текущего распознавания

Профиль и изображения проверок взяты из одной записи одного интерфейса. Это
не универсальный распознаватель физического покерного стола. В отдельном архиве есть девять шаблонов:
`6c`, `Qd`, `Tc`, `2h`, `Kh`, `Ah`, `Th`, `Kc`, `Qc`. Остальные 43 карты, в том числе
все пики, отсутствуют в наборе. Порог сходства и отрыв от второго кандидата могут
отклонить неуверенное чтение, но не гарантируют отказ на любой неизвестной карте.

Перекрытые карты не сдвигаются в соседние позиции. Несовпадение количества карт
с этапом оставляет весь борд нечитаемым. REPLAY и AWARDED не превращаются в текущий
банк; видеозапись остаётся источником `recording` даже при надписи LIVE в кадре.
Стеки, места, карты героя, очередь хода и история ставок пока не распознаются.
Произвольный ракурс камеры, другой шрифт и раскладка требуют отдельной проверки.

## Дополнительный серверный режим

В `.env` на сервере установить:

```dotenv
VISION_MODE=live
OPENAI_API_KEY=your-server-api-key
OPENAI_VISION_MODEL=gpt-4.1-mini
RECEIVER_TOKEN=your-private-random-token-at-least-24-characters
VISION_TIMEOUT_SECONDS=15
```

Перезапустить сервер. В интерфейсе появится LIVE и выбранная модель. Поле токена
в интерфейсе предназначено для `RECEIVER_TOKEN`, ключ OpenAI туда не вводится.
Ключ OpenAI не передаётся в браузер и не входит в записи. Реальные API-вызовы
платные. Модель настраивается переменной окружения; ответ проверяется независимо
от её уверенности. Отказ, таймаут и некорректный JSON видны как ошибки, без перехода
на mock.

По умолчанию передаётся весь выбранный видеокадр, включая области вне контуров.
Контуры управляют отбором и помогают модели сопоставить места. Перед началом
направить камеру на стол так, чтобы в кадр не попадали ненужные окна. Маска
детектора не является скрытием части изображения при отправке.

Для серверного режима установить также `uv sync --frozen --extra dev`, скопировать
`.env.example` в `.env`, собрать `npm run build`, затем запустить:

```bash
uv run uvicorn app.vision.api:app --host 127.0.0.1 --port 8001 --workers 1
```

Открыть `http://localhost:8001/server.html` и ввести `RECEIVER_TOKEN`. Mock здесь
проверяет доставку и детектор; он намеренно не изображает успешное чтение карт.
Корневая страница этого же сервера остаётся локальным режимом.

## Проверки и развитие

- `npm run verify` — TypeScript, Prettier/Ruff, архитектурные границы, Vitest,
  весь pytest, production-сборка и ASGI-проверка выдачи HTML/JS/CSS/OCR/WASM.
- `npx vitest run web/local` — парсер, очередь, жизненный цикл и карточные проверки.
  Без отдельного архива два теста на записи будут явно пропущены.
- `npm run test:recording` — реальные OCR-кропы с закреплённой моделью и карточные
  изображения из записи. Сначала распаковать `table-vision-recording-fixtures.zip`
  в корень репозитория. Команда выдаст ошибку, если входных файлов нет; сами
  изображения исключены из Git и не нужны для запуска сайта.
- `npx vite-node scripts/build-card-templates.ts` — воспроизводимая сборка шаблонов
  в `tests/vision-fixtures/templates.json` из размеченных кадров Replay;
  Live-кадры используются для регрессии. Набор изображений требуется локально.
- `npm run benchmark` — чистый детектор на синтетических кадрах Node. Это не FPS
  браузера и не замер OCR на камере пользователя.
- `npm run verify:step -- 04` — проверки этапа исходного серверного плана 01…12.

Контракты и зависимости описаны в [ARCHITECTURE.md](ARCHITECTURE.md), фактические
проверки и ограничения — в [PROGRESS.md](PROGRESS.md), происхождение тестовых
изображений — в [../../tests/vision-fixtures/README.md](../../tests/vision-fixtures/README.md).
Чистые модули полей, карт и очереди развиваются отдельно от DOM, камеры и OCR Worker.
Добавление нового формата наблюдений требует новой версии контракта и адаптера.

`docker compose -f docker-compose.vision.yml up --build` обслуживает оба интерфейса
на `127.0.0.1:8001`. Для камеры с другого устройства требуется HTTPS. Серверный
режим однопроцессный; локальный режим имеет собственную очередь в каждой вкладке.
Существующий мост запускается отдельно через `app.main:app` на порту 8000.
Локальный JSON не отправляется в его `/v1/events`: будущему адаптеру нужны
отдельные проверки полноты, свежести, идентичности раздачи и готовности к решениям.
