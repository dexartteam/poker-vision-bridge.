# Порядок работы и проверки

Исходные пошаговые промпты сохранены в `CODEX-PROMPTS.md`, исходный дизайн — в
`DESIGN.md`. Они описывают целевую программу пилота, включая реальные видео и live
оценку, и не являются отчётом о выполненных проверках. Фактическая реализация
адаптирована к существующему Python-репозиторию согласно `ARCHITECTURE.md`.

Для дальнейшей работы запускать `npm run verify:step -- NN` после соответствующего
изменения. Команда проверяет TypeScript, lint и архитектурные границы, запускает
всю небольшую браузерную unit-suite и указанную Python-группу. Неизвестный номер
завершается ошибкой. Пустая Python-группа также не может пройти. Npm выбран как
единственный менеджер JS-зависимостей; используется package-lock.json.

проверены реализованные границы MVP. Перспектива, реальный OCR-корпус, измеренная
точность на устройстве, полноценные browser E2E и live smoke требуют следующей
приёмки. До неё ветка остаётся draft и не считается готовой к роботу.

## Ручная приёмка на устройстве

1. `npm run verify`, затем запустить собранное приложение по README.
2. В mock-режиме запустить демо, изменить сцену один раз. Revision растёт,
   после успокоения приходит один запрос, повтор спокойных кадров не создаёт поток.
3. Открыть камеру, проверить фактическое разрешение и читаемость цифр. Настроить
   все seat/board/pot/hero/controls области, маски таймеров и единицы сумм.
4. Оставить стол неподвижным, записать число запросов за минуту и длительность
   детектора. Пошевелить один значимый объект/цифру, потом только таймер в маске.
5. Отключить камеру, скрыть вкладку, остановить локальный видеофайл. Отправка должна
   прекратиться; новый запуск доступен; запись можно скачать после остановки.
6. Проверить отказ в доступе к камере и сетевую ошибку. UI не показывает confirmed.
7. Настроить live на сервере. Ограничить первый прогон вручную несколькими кадрами,
   скачать запись, сравнить JSON с картинками и разметить каждое поле человеком.
8. Измерить пропуски значимых изменений, ложные отправки, p50/p95 задержки и долю
   правильно распознанных карт/сумм. Записать устройство, браузер, освещение,
   ракурс, разрешение, профиль, модель и версию промпта.
9. Сверить результаты с целевыми пунктами шага 11 исходного плана. При ошибках
   добавить исходное видео/кадры и регрессию, затем менять конкретный модуль.

Ни демо, ни mock-адаптер, ни синтетический benchmark не заменяют эту приёмку.
