# Отладка распознавания по записи

Откройте `/replay.html`, выберите видео PokerStars classic и шаблоны карт,
проверьте области. Режим связывает кадр, частичное распознавание, список недостающих
полей и ответ PokerAI. На подтверждённом ходе героя воспроизведение останавливается;
после ответа кадр остаётся на экране для сравнения. Продолжение — отдельной кнопкой.
Если активные кнопки героя не распознаны, остановите нужный кадр вручную.

Распознавание остаётся локальным. На сервер передаётся JSON, а не видео или кадр.
Обычный интерфейс первого этапа не отправляет данные в солвер. Запись не становится
живым столом Open Poker: replay не создаёт VisionEvent, не использует Coordinator,
Telegram или исполнитель действий. В каждом ответе `execution: "disabled"`.

## Запуск

```bash
npm ci
uv sync --extra dev
npm run build
uv run uvicorn app.replay.api:app --host 127.0.0.1 --port 8002 --workers 1
```

Открыть `http://127.0.0.1:8002/replay.html`.

Для разработки запустить этот Python-сервер и отдельно `npm run dev`, затем открыть
`http://localhost:4173/replay.html`: Vite проксирует `/v1/replay` на порт 8002.

Для настоящего ответа в серверном `.env` нужны:

```dotenv
RECEIVER_TOKEN=replace-with-a-private-random-token-at-least-24-characters
POKERAI_API_KEY=gto_your_server_key
POKERAI_BASE_URL=https://pokerai.bet
POKERAI_TIMEOUT_SECONDS=20
PREFLOP_VERSION=6max
FLOP_VERSION=6max
REPLAY_ALLOWED_ORIGINS=[]
```

В браузере вводится только `RECEIVER_TOKEN`. Ключ PokerAI остаётся на сервере.
`SOLVER_MODE`, Telegram и настройки автоматического исполнения replay не читает.
Если ключа PokerAI нет, диагностика продолжает работать, полный контекст получает
статус `not_configured`. Тестовый ответ вместо настоящего не подставляется.

GitHub Pages обслуживает только интерфейс. Для запросов из Pages нужен доступный
по HTTPS replay-сервер; его серверный CORS настраивается явно, например:

```dotenv
REPLAY_ALLOWED_ORIGINS='["https://dexartteam.github.io"]'
```

При раздаче интерфейса самим Python-сервером CORS не требуется. Произвольные origins
и wildcard не включаются. Сервер проверяет Bearer-токен независимо от CORS.

## Какие сведения действительно отсутствуют

Наблюдение `local-vision.observation.v2` частичное. Оно не содержит полной истории
действий, надёжного идентификатора раздачи и решения, блайндов, дилера и позиционной
карты. `chip_display` может означать ставку или выигрыш; пустое поле не доказывает 0.
Видимые кнопки дают названия действий, но ещё не полный набор точных ограничений.
Не установлено, включает ли `pot_display` текущие ставки.

Диагностика выдаёт все обнаруженные пробелы сразу. JSON-черновик содержит известные
карты, улицу и стеки; неизвестные значения остаются `null`. Поле `pot` означает
общий банк **с текущими ставками**. `bet_to` — суммарный взнос игрока на текущей
улице. `contribution` каждого действия — добавленные именно этим действием фишки.
`raise_to`, `min_to`, `max_to` — абсолютные суммы, не прибавки к текущей ставке.
Денежные значения допустимо вводить строками, чтобы сохранить десятичную точность.

Для первого сравнения можно заполнить недостающие игровые поля вручную и отдельно
подтвердить полную историю с начала раздачи. Это явная ручная разметка данного
кадра, а не восстановленная распознавателем история. Подтверждение привязано
к epoch, frame_seq, revision и media_time; после смены кадра оно неприменимо.
Известные прочитанные поля нельзя незаметно заменить ручными значениями — конфликт
показывается отдельной ошибкой. Непрочитанную карту дополнить можно.

Проверки сопоставляют банк с суммой взносов, ставки с историей текущей улицы,
пас со статусом игрока, суммы блайндов, raise-to и допустимые суммы. Эти проверки
находят противоречия, но не доказывают полноту произвольно введённой вручную истории.
Пропуски при перемотке или между редкими кадрами должны проверяться по записи.
Возвраты неуравненных ставок и списания, не представимые текущим форматом истории,
дают несогласованный банк; их нельзя компенсировать выдуманными действиями.

## HTTP-контракт

- `GET /v1/replay/status` — наличие настройки PokerAI, провайдер и запрет исполнения;
  без ключей и токенов.
- `GET /v1/replay/schema` — JSON Schema игровых полей, с Bearer-токеном.
- `POST /v1/replay/analyze` — диагностика или расчёт, с Bearer-токеном.

```typescript
type ReplayRequest = {
  schema_version: 'replay.request.v1';
  session_id: string;
  request_id: string;
  action: 'diagnose' | 'solve';
  observation: PokerStarsObservation;
  confirmed_context?: {
    provenance: 'manual';
    source_epoch: string;
    frame_seq: number;
    revision: number;
    media_time: number;
    history_confirmed: boolean;
    values: Record<string, unknown>;
  };
};
```

`values` дополняет игровые поля из возвращённого `draft_observation`: `hand_id`,
`street`, `dealer_seat`, `acting_seat`, `blinds`, `hero`, `board`, `pot`, `seats`,
`action_history`, `legal_actions`, `hero_turn`, `turn_id`, `pokerai`.
Объекты дополняются по ключам; массивы заменяются целиком. Transport, platform,
bot_only, API-ключи и команды исполнения в этих данных отсутствуют.

```typescript
type ReplayResponse = {
  schema_version: 'replay.response.v1';
  session_id: string;
  request_id: string;
  frame: {
    source_epoch: string;
    frame_seq: number;
    revision: number;
    media_time: number | null;
  };
  status:
    | 'missing_data' | 'invalid' | 'unsupported' | 'ready'
    | 'not_configured' | 'solved' | 'solver_failed';
  issues: Array<{
    code: string;
    field: string;
    message: string;
    kind: 'missing' | 'invalid' | 'unsupported' | 'configuration' | 'warning';
  }>;
  solver: { provider: 'pokerai.bet'; configured: boolean };
  execution: 'disabled';
  draft_observation: Record<string, unknown>;
  normalized_observation: Record<string, unknown> | null;
  solver_request: Record<string, unknown> | null;
  solver_result: SolverResult | null;
  manual_fields: string[];
  elapsed_ms: number;
};
```

`diagnose` не вызывает сеть. `solve` повторяет все проверки и вызывает только
существующий адаптер PokerAI. Из ответа показывается вся смесь действий и частот,
без локальной замены отсутствующего результата. Сумма частот и каждая ненулевая
ветвь проверяются; невалидная стратегия остаётся видимой со статусом `invalid`
или `solver_failed`, а не как успешное решение.

Повтор того же `session_id/request_id` и идентичного запроса не расходует квоту
второй раз: последние 128 завершённых вызовов сохранены в памяти одного процесса.
Повтор идентификатора с изменённым кадром/контекстом получает HTTP 409.
После перезапуска сервера этот кэш теряется. Автоматических повторов после
таймаута/ошибки провайдера нет; транспортная ошибка не доказывает отсутствие
расхода квоты у провайдера. Идентификатор нового запроса используют для явного
повтора или нового кадра. Публично доступный сервер должен иметь собственные
ограничения доступа и квот; этот однопроцессный стенд не является multi-tenant API.

## Границы солвера

| Ситуация | Что делает текущий адаптер |
| --- | --- |
| Префлоп | Первый добровольный ход героя, полная карта шести позиций, история с SB/BB, без анте; глубина около 100 BB или 40 BB для соответствующей базы |
| Флоп | Два оставшихся игрока, тип банка и роли, точный путь узла готового дерева, совпадение банка и эффективного стека |
| Тёрн/ривер | `unsupported`: нужен отдельный путь диапазонов и асинхронного расчёта |
| Постфлоп с несколькими соперниками | `unsupported` |

Для флопа каждое уже совершённое действие этой улицы требует `node_label` из дерева
PokerAI. `node_id` должен совпадать с `root/<метка первого действия>/...`. Строку
нельзя вычислять просто из надписи OCR, а произвольный размер ставки может не иметь
узла в готовом дереве. Роли должны соответствовать участвующим игрокам.

Официальные контракты проверены 29.09.2026:
[документация PokerAI](https://pokerai.bet/docs),
[OpenAPI](https://pokerai.bet/openapi.en.json).
Неподдерживаемая ситуация — ограничение текущего адаптера, а не обязательно ошибка
распознавания. Отсутствующий ключ и сетевой сбой также имеют отдельные статусы.

## Проверки

```bash
uv run pytest tests/replay tests/test_solver.py tests/test_solver_boundaries.py
npm run verify
```

Backend-проверки охватывают неизвестные значения и историю, ручное подтверждение
конкретного кадра, конфликты и некорректные вложенные структуры, отсутствие ключа,
подготовку настоящего контракта, идемпотентность, ошибки и неверные ответы провайдера,
аутентификацию и CORS. Реальный оплачиваемый запрос PokerAI требует серверного
ключа; unit-тесты его не выполняют.
